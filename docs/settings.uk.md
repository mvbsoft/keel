# Налаштування keel

[English](settings.md)

Усі налаштування keel: що вони роблять, їхні значення, де зберігаються і до кого застосовуються.

## Де діє налаштування

Кожне налаштування має одне з трьох місць:

| Місце | Застосовується до | Зберігається в | У git |
|---|---|---|---|
| **Цей ПК** | кожного проєкту на цьому комп'ютері | `~/.claude/settings.json`, `~/.claude/keel/` | ні |
| **Цей проєкт** | цього проєкту, для всіх, хто над ним працює | `.keel/config.json` | так, спільне з командою |
| **ПК або проєкт** | кожного проєкту на цьому комп'ютері, якщо проєкт не задає власного значення | ПК: як вище; проєкт: `.claude/settings.local.json` або `.keel/local/options.json` | ні, особисте |

**Правило:** власне значення проєкту має перевагу над значенням ПК. Приберіть значення проєкту, і
знову діє значення ПК. Один виняток: `prompt_preview` проєкт може лише вимкнути. Коли значення ПК
вимкнене, увімкнене значення проєкту нічого не змінює.

Приклад: ПК стискає розмови на 300 000 токенів. Один великий проєкт задає для себе 500 000. Сесії в
цьому проєкті стискаються на 500 000; усі інші проєкти й далі стискаються на 300 000.

## Як їх задати

| Коли | Що задає |
|---|---|
| Встановлення keel | дві опції плагіна нижче, як значення **ПК** |
| `/keel:configure` у проєкті | спершу питає: цей проєкт чи лише цей ПК. Режим проєкту задає налаштування проєкту, а для налаштувань «ПК або проєкт» показує обидва значення й дає залишити значення ПК або задати значення для проєкту. Перше налаштування також питає: **швидке** (рекомендовано, близько шести питань; решта значень — рекомендації keel) чи **детальне** (кожен розділ; обидва спершу пояснюють кожну групу питань) |
| `/keel:configure machine` | лише значення ПК, для всіх проєктів |
| `/keel:configure check` | які розділи пройти знову після останнього configure і чому; налаштувань не змінює |
| `/keel:configure <section>[,<section>...]` | ці розділи знову, запис один раз наприкінці (`gates,git`); розділи: `languages`, `scan`, `gates`, `git`, `verification`, `code`, `plugins`, `docs`, `migration`, `settings`, `usage` або `prices` |

Нічого не пишеться без вашого «так». Для файлів налаштувань Claude Code і таблиці цін keel робить
резервну копію, перш ніж їх змінити (файли проєкту в `.keel/local/backups/`, файл ПК поруч із собою).

### Встановлення для одного проєкту

keel працює лише в проєкті, де є `.keel/config.json` — файл, який пише `/keel:configure`. У будь-якому
іншому проєкті його хуки нічого не додають до розмови, Claude не може сам підвантажити його навички
(configure і help запускаються лише тоді, коли ви їх вводите), а його агенти відхиляються, доки `/keel:configure` не створить папку
`.keel/`. Команда keel, яку ви там введете, спершу пропонує запустити `/keel:configure`. Дві речі
працюють усюди: запис того, з якого гаманця платить сесія, і статус-рядок. Якщо keel встановлено для
вашого користувача, його агенти й навички все одно видно в кожному проєкті, бо їх перелічує Claude Code.

`claude plugin install keel@keel --scope project` (для всіх, хто працює в репозиторії) або
`--scope local` (лише для вас, у цьому репозиторії) вмикає keel лише в одному репозиторії. Область
визначає лише те, **де keel увімкнено**. Відповіді на питання під час встановлення (мова розмови,
Opus) усе одно зберігаються для всього ПК: Claude Code тримає опції плагіна в налаштуваннях
користувача й ігнорує їх у файлах проєкту, тому клонований репозиторій не може їх змінити. Щоб дати
одному проєкту власну мову або вибір Opus, запустіть у ньому `/keel:configure` і оберіть «задати для
проєкту»; keel тоді збереже це значення в `.keel/local/options.json` проєкту.

## Обов'язкові й необов'язкові

Детальне налаштування питає про кожен розділ. **Обов'язкові** розділи не можна пропустити, але можна
прийняти пропозицію однією відповіддю: мова репозиторію, гейти, git, пороги перевірки, розміри файлів
і рівень коментарів, профіль документації. Усе інше **необов'язкове**: пропуск лишає типове значення
або значення ПК.

Швидке налаштування питає лише те, що потребує вас (мови, команди гейтів, режим git і головну гілку
та ще кілька питань, коли вони доречні), а решту бере з рекомендацій keel. Його підсумок перелічує
кожне значення, про яке воно не питало, з розділом, який його змінює.

## ПК або проєкт

| Налаштування | Що робить | Значення | Типово | Що радить keel |
|---|---|---|---|---|
| `conversation_language` | мова, якою keel говорить, питає, звітує й планує | код мови: `en`, `uk`, `de`... | `en` | ваша мова |
| `allow_opus` | вимкнено: агенти keel, які мали б працювати на Opus, працюють на Sonnet (дешевше, менш ретельно) | увімкн. / вимкн. | увімкн. | увімкн. |
| `autoCompactWindow` | на скількох токенах Claude Code стискає розмову; [попередження про контекст](under-the-hood.uk.md#що-працює-само) від keel з'являється на 90 % від цього значення (від `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, коли його задано), не більше за власне вікно моделі; значення менше за 100 000 тут ігнорується (змінна оточення піднімається до 100 000) | кількість токенів | власне значення Claude Code (близько 967k для моделі з 1M) | 300 000 |
| `showClearContextOnPlanAccept` | після схвалення плану запропонувати почати роботу лише з плану, без розмови про планування | увімкн. / вимкн. | вимкн. | увімкн. |
| `bashOutputMaxChars` | вивід команди довший за це йде у файл із прев'ю замість розмови | символи | 30 000 | 15 000 |
| `attribution` | рядок «generated with» і співавтор у комітах та pull request | об'єкт підпису Claude Code | Claude Code додає їх | немає |
| `prompt_preview` | надсилати перші 100 символів кожного запиту (секрети приховано) на вашу сторінку витрат. Проєкт може його лише вимкнути: коли значення ПК вимкнене, увімкнене значення проєкту нічого не змінює | увімкн. / вимкн. | увімкн. | на ваш вибір |

Чому 300 000 для стиснення: кожен запит перечитує всю розмову. На Opus запит на 600k токенів коштує
близько $0.12 за читання кешу, на 300k — близько $0.06. Ціна меншого вікна в тому, що подробиці з
початку розмови втрачаються при кожному стисненні частіше.

Де лежать значення: значення ПК для перших двох — це опція плагіна keel; для `prompt_preview` —
`~/.claude/keel/usage.json`; решта — у `~/.claude/settings.json`. Власне значення проєкту для
`conversation_language`, `allow_opus` і `prompt_preview` лежить у `.keel/local/options.json`, для
інших — у `.claude/settings.local.json`.

## Цей ПК

У `~/.claude/keel/usage.json`, якщо не сказано інакше. Задається в `/keel:configure` (розділ «Usage
and costs») або `/keel:configure machine`, крім `history_days`: configure ніколи про нього не питає,
ви редагуєте файл самі.

| Налаштування | Що робить | Значення | Типово |
|---|---|---|---|
| `statusLine` (у `~/.claude/settings.json`) | статус-рядок; власний від keel або ваш, обгорнутий, щоб keel міг записувати відсотки лімітів плану | keel / обгорнути ваш / немає | немає |
| `wallet_default` | гаманець сесії, яку хук keel не позначив на її початку; позначена сесія — це `api` з ключем, токеном чи помічником API (або Bedrock, Vertex, Foundry, Mantle), `cloud_wallet` у вебі, інакше `subscription` | `subscription` / `api` / `credit` | `subscription` |
| `cloud_wallet` | як платить Claude Code у вебі | `subscription` / `api` / `credit` | `credit` |
| `also_api` | цей ПК використовує і підписку, і ключ API. Увімкн.: сесія, яку хук keel не позначив, показується як `unknown` замість `wallet_default` і не входить у калібрування лімітів | увімкн. / вимкн. | вимкн. |
| `pc` | назва цього ПК на сторінці витрат | від 1 до 40 літер, цифр, `-`, `_` | назва комп'ютера |
| `user` | ваше ім'я на сторінці витрат, щоб розрізняти людей на командній сторінці | текст | ваш git email |
| `history_days` | на скільки днів назад сягає перша синхронізація зі сторінкою витрат (а також перша синхронізація після зміни адреси сторінки); наступні синхронізації надсилають те, що змінилося після попередньої | дні | 30 |
| `artifact_url` | адреса вашої приватної сторінки «keel usage» | посилання claude.ai | немає |
| `approved_artifact_urls` | адреси командних сторінок із конфігурацій проєктів, на які ви дозволили надсилати цьому ПК; використовуються, лише поки `artifact_url` не задано | посилання claude.ai | немає |
| автономний git (у `trusted-git.json`) | проєкти, у яких ви в запиті Claude Code підтвердили, що keel може виконувати свої git-кроки (гілка, коміт, оновлення з головної гілки, пуш) без запиту щоразу (пуш із головної гілки йде через ваші звичайні дозволи; злиття все одно питає, якщо `git.ask_before_merge` не вимкнено), з відбитком налаштувань `git` проєкту: коли вони змінюються, keel знову питає, доки ви не підтвердите ще раз | записує `git-flow.js trust` | немає |
| ціни (у `prices.json`) | ваша власна таблиця цін, яку пише `/keel:configure prices` | таблиця цін | вбудована таблиця keel |

## Цей проєкт

У `.keel/config.json`, закомічено й спільне з командою. ★ позначає налаштування, яке має бути в кожній
конфігурації; `/keel:configure` записує його завжди (швидке налаштування для деяких із них бере
рекомендацію, не питаючи).

| Налаштування | Що робить | Значення | Типово |
|---|---|---|---|
| ★ `schema_version` | версія формату конфігурації; її записує `/keel:configure`, не редагуйте її | `1` | `1` |
| ★ `repo_language` | мова того, що keel пише в репозиторій: повідомлення комітів, нотатка, пам'ять, журнали сесій, нові документи | код мови малими літерами, за потреби з регіоном: `en`, `uk`, `pt-BR` | `en` |
| ★ `gates.checks` | команди, які keel запускає як гейти: тести, лінтери, перевірки типів, по частинах монорепозиторію | команди | пропонується зі сканування проєкту |
| ★ `gates.security_scanners` | сканери безпеки, що запускаються з гейтами; сканер, якого не встановлено, — це явне попередження, а не збій. Команда може починатися зі шляху від папки проєкту (`./gradlew …`, `.venv/bin/bandit …`); просте ім'я шукається в PATH | команди | пропонується зі сканування |
| ★ `git.mode` | хто виконує git: ви (keel пише повідомлення коміту й не виконує жодного git-кроку, про який ніхто не просив) або keel (коміт, оновлення з головної гілки, пуш; злиття — як каже `git.ask_before_merge`). В обох режимах keel виконує те, про що ви просите: гілку, яку ви обираєте на початку задачі, ваші власні git-кроки | `manual` / `autonomous` | немає: `/keel:configure` питає й радить `manual` для першого проєкту |
| ★ `git.main_branch` | головна гілка | назва гілки | з репозиторію |
| ★ `git.ask_before_merge` | автономний режим. Увімкн.: keel зливає в головну гілку лише тоді, коли про це просить ваша інструкція (`/keel:end-task заверши й злий у main`), і Claude Code просить вас підтвердити. Вимкн.: завершення задачі чи лінії роботи теж зливає; без питань — лише після того, як ви підтвердили автономний режим на цьому ПК, інакше Claude Code питає | увімкн. / вимкн. | увімкн. |
| ★ `git.state_in_git` | тримати нотатку, пам'ять і журнали сесій у git. `/keel:configure` застосовує його, перелічуючи їх у `.keel/.gitignore`; саме значення не змінює того, що зберігає git, тому змінюйте його через `/keel:configure git`, а не вручну | увімкн. / вимкн. | увімкн. |
| ★ `verification.tier_rules.gates_only_max_files` | зміні до стількох файлів, жоден з яких не змінює поведінку (текст, коментарі, документація), пропонуються лише гейти | файли | 1 |
| ★ `verification.tier_rules.basic_max_modules` | зміну в такій кількості модулів або меншій пропонується перевіряти на рівні Basic; більше модулів — Standard | модулі | 1 |
| ★ `verification.tier_rules.large_change_lines` | від цього розміру зміна велика (Standard) | рядки | 400 |
| ★ `verification.tier_rules.very_large_change_lines` | від цього розміру зміна дуже велика (Maximum) | рядки | 1000 |
| `verification.tier_rules.core_fan_in` | зміна у файлі, який імпортує стільки файлів, є ключовим кодом (Maximum) | файли | 5 |
| ★ `verification.verifier_caps` | скільки перевіряльників може перевіряти знахідки на кожному рівні | числа для basic, standard, maximum | 2, 5, 8 |
| ★ `architecture.file_lines_warn` | файл довший за це отримує попередження | рядки | 700 |
| ★ `architecture.file_lines_max` | файл довший за це є знахідкою | рядки | 1000 |
| `comments.level` | скільки коментарів пише keel: лише складний код, плюс рядок на кожну публічну функцію, або більше. Детальне налаштування питає його завжди; швидке бере рівень, найближчий до наявного коду проєкту | `short` / `functions` / `detailed` | `short` |
| `comments.ticket_prefixes` | префікси ідентифікаторів тікетів (ABC для ABC-123), про які повідомляється, коли вони трапляються в нових коментарях і документах | префікси: велика літера, далі великі літери або цифри | немає |
| `comments.adr_refs` | чи дозволено згадки записів про рішення (ADR-12) у коментарях і документах | `allowed` / `forbidden` | `allowed` |
| `comments.refs_exempt` | додаткові файли, де ідентифікатори є предметом і про них не повідомляється; вбудовані (записи про рішення, папки задач і тікетів, журнали змін, `.keel/`) діють завжди | glob-шаблони | немає |
| ★ `docs.profile` | скільки документації пише keel: 1 тримати документи правдивими, 2 + ADR, 3 + специфікація на функцію, 4 важкий | 1-4 | 1 |
| ★ `docs.pattern` | куди йдуть нові документи (профілі 3-4). Наявні документи побічно не переносяться: коли детальне налаштування обирає шаблон, якого ваші документи ще не дотримуються, keel пропонує підготувати перенесення як окрему задачу ([ваші наявні документи](getting-started.uk.md#3-налаштування-проєкту-keelconfigure)) | `none` / `diataxis` / `arc42` / `arc42-c4` | `none` |
| `delegation.min_plan_steps`, `min_plan_files` | від такого розміру плану keel пропонує передати кроки агентам-виконавцям | кроки, файли | 8, 15 |
| `cleanup.trash_max_age_days` | `/keel:cleanup empty-trash` типово видаляє партії кошика такого віку або старші | дні | 30 |
| `tasks.in_git` | де лежать папки незакінчених задач: `true` у `.keel/tasks/<id>/`, комітяться на гілці задачі, тож команда їх бачить; `false` у `.keel/local/tasks/<id>/`, лише цей ПК. Дивіться [два способи працювати](workflows.uk.md#де-лежать-файли) | увімкн. / вимкн. | увімкн. |
| `stack_skills` | плагіни стеку, які ви обрали (для інформації) | назви | немає |
| `usage.artifact_url` | сторінка витрат, спільна для команди. ПК надсилає на неї лише після того, як його користувач її схвалить, і лише поки ПК не має власного `artifact_url`. Тоді вона отримує витрати цього ПК з **усіх** його проєктів (назви папок проєктів, гілки, прев'ю запитів, якщо їх не вимкнено), а не лише з цього | посилання claude.ai | немає |

`.keel/profile.json`, теж закомічений, містить те, що знайшло сканування проєкту і що ви підтвердили:
частини проєкту, їхні мови й команди, секретні файли за шляхом. Його `run_command` для кожної частини —
це команда, що запускає застосунок; її використовує агент QA (або `null`, коли такої немає). Профіль
змінюють через `/keel:configure scan`.

Ще два налаштування проєкту є особистими й лежать у `.claude/settings.local.json` (поза git; коли
git ще не ігнорує цей файл, `/keel:configure` пропонує додати його в `.gitignore`):

| Налаштування | Що робить | Що пише keel |
|---|---|---|
| `plansDirectory` | де Plan Mode зберігає файли планів | `./.keel/local/plans/claude` (до keel 1.3: `./.keel/local/plans`; `/keel:configure` пропонує перенести старі плани) |
| `permissions.allow` | команди, що запускаються без запиту дозволу | підтверджені вами команди гейтів |

## Приклади

Чотири зразкові конфігурації. Це приклади, а не рекомендації копіювати: значення підібрано, щоб
показати, як налаштування стикуються між собою. Кожен фрагмент проєкту показує лише важливі ключі;
решта обов'язкових ключів лишається такою, як її написав `/keel:configure`.

### а) Самостійний розробник на підписці

Git вручну й перевірка, що для більшості змін лишається на рівні Basic.

`.keel/config.json` (уривок):

```json
{
  "git": { "mode": "manual", "main_branch": "main", "ask_before_merge": true, "state_in_git": true },
  "verification": {
    "tier_rules": {
      "gates_only_max_files": 1,
      "basic_max_modules": 2,
      "large_change_lines": 600,
      "very_large_change_lines": 1000
    }
  }
}
```

Basic пропонується для змін у до 2 модулях (типово 1), а Standard лише від 600 рядків (типово 400).
Maximum усе ще починається з 1000 рядків. keel дає повідомлення коміту й не виконує жодного
git-кроку, про який ви не просили.

`~/.claude/settings.json` (цей ПК):

```json
{ "autoCompactWindow": 300000, "bashOutputMaxChars": 15000 }
```

Стиснення на 300 000 токенів і вивід команд, обрізаний на 15 000 символів: значення, які радить keel.

### б) Командний репозиторій

Автономний git із підтвердженням перед кожним злиттям, без згадок записів про рішення в коді та з
перевіркою префіксів тікетів.

`.keel/config.json` (уривок):

```json
{
  "git": { "mode": "autonomous", "main_branch": "main", "ask_before_merge": true, "state_in_git": false },
  "tasks": { "in_git": false },
  "comments": {
    "level": "short",
    "ticket_prefixes": ["PROJ", "SHOP"],
    "adr_refs": "forbidden",
    "refs_exempt": ["docs/debt-register.md"]
  },
  "docs": { "profile": 2, "pattern": "none" },
  "usage": { "artifact_url": "https://claude.ai/artifact/EXAMPLE" }
}
```

`ask_before_merge: true` означає, що keel зливає лише тоді, коли ви про це просите, і Claude Code
просить вас підтвердити злиття. `state_in_git: false` тримає нотатку, пам'ять і журнали сесій поза git
(репозиторій команди лишається чистим); `/keel:configure git` задає його й перелічує ці файли в
`.keel/.gitignore`. `tasks.in_git: false` робить те саме з папками задач: вони лишаються на ПК
кожного розробника і не їздять на гілках задач. `ticket_prefixes` і `adr_refs` змушують keel
повідомляти про `PROJ-123` та `ADR-12` у нових коментарях і документах. `refs_exempt` перелічує файл,
де такі ідентифікатори є предметом. Профіль 2 додає ADR для значущих рішень. `usage.artifact_url` —
це заповнювач для сторінки витрат, спільної для команди; кожен ПК надсилає на неї лише після того, як
його користувач її схвалить, а ПК із власним `artifact_url` і далі надсилає туди. Схвалений ПК
надсилає витрати з усіх своїх проєктів, а не лише з цього, тож команда бачить і назви папок, і гілки
тих проєктів (і прев'ю запитів, якщо їх не вимкнено). Кожен розробник один раз підтверджує
автономний режим на власному ПК.

### в) Великий монорепозиторій із власними налаштуваннями

Проєкт, якому потрібне більше вікно стиснення й інша мова розмови, ніж на ПК.

`.keel/config.json` (уривок):

```json
{
  "gates": {
    "checks": [
      { "part": "services/api", "kind": "test", "command": "npm test --workspace services/api" },
      { "part": "services/web", "kind": "test", "command": "npm test --workspace services/web" },
      { "part": "services/web", "kind": "lint", "command": "npm run lint --workspace services/web" }
    ],
    "security_scanners": [{ "name": "npm audit", "command": "npm audit" }]
  },
  "verification": {
    "tier_rules": {
      "gates_only_max_files": 1,
      "basic_max_modules": 1,
      "large_change_lines": 400,
      "very_large_change_lines": 1000,
      "core_fan_in": 15
    }
  }
}
```

`.claude/settings.local.json` (особисте, поза git):

```json
{ "autoCompactWindow": 500000 }
```

`.keel/local/options.json` (особисте, поза git):

```json
{ "conversation_language": "de" }
```

Сесії в цьому проєкті стискаються на 500 000 токенів, а keel говорить тут німецькою; усі інші проєкти
лишають значення ПК. Значення проєкту має перевагу над значенням ПК. `core_fan_in: 15` піднімає межу,
від якої зміна у файлі, що його широко імпортують, вважається ключовим кодом (типово 5), бо в
монорепозиторії багато файлів спільно використовують кілька бібліотек.

### г) Проєкт, що вимикає прев'ю запитів

Для проєкту з чутливими запитами: тоді сторінка витрат не отримує ні тексту запитів, ні назви задачі,
а назви кроків стають «step 1», «step 2».

`.keel/local/options.json` (лише цей проєкт):

```json
{ "prompt_preview": false }
```

Щоб вимкнути їх для кожного проєкту на ПК, задайте `prompt_preview` як `false` у
`~/.claude/keel/usage.json` або дайте відповідь на питання в `/keel:configure usage`. Проєкт не може
знову їх увімкнути, поки значення ПК вимкнене. Що саме надсилається, дивіться в
[панелі витрат](usage-dashboard.uk.md#що-потрапляє-на-сторінку-і-що-не-потрапляє-ніколи).
