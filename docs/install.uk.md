# Встановлення, оновлення й видалення keel

[English](install.md)

keel — плагін для Claude Code; його встановлюють один раз на ПК (або для одного проєкту, дивіться
[області встановлення](#область-встановлення)). Ця сторінка про вимоги, встановлення, що змінює keel,
оновлення, видалення й типові проблеми. Налаштування проєкту після встановлення:
[Початок роботи](getting-started.uk.md).

## Вимоги

1. **[Node.js](https://nodejs.org) 22 або новіший.** Усі скрипти та хуки keel працюють на Node. Сам
   Claude Code Node не потребує, тож перевірте командою `node --version`. Зі старішим Node команди
   keel зупиняються з однорядковим повідомленням про те, як його оновити; без Node взагалі хуки й
   команди keel просто не працюють.
2. **[Claude Code](https://code.claude.com/docs) 2.1.296 або новіший** (версія, на якій keel
   перевірено). Підтвердження keel і звіти агентів спираються на нові можливості хуків; на старішій
   версії вони можуть не працювати, а сам keel версію не перевіряє. Сьогодні keel працює в Claude Code; інших агентів для
   програмування заплановано.
3. **git.** Кожна задача живе на власній гілці, а перевірка дивиться на те, що змінилося в git: для
   задачі — усе на її гілці від базової гілки; для сесії — усе від початку сесії. У папці, яка не є
   репозиторієм git, keel пропонує `git init` і перший коміт або зупиняється.
4. **Windows, macOS або Linux.** keel розробляють і щодня використовують на Windows 11; набір тестів
   також працює на Linux (Node 22 у Docker), а CI запускає його на всіх трьох системах. Статус-рядок
   keel працює в PowerShell на Windows і в bash деінде; його значки показуються й у bash 3.2 (який
   постачається з macOS), і без локалі UTF-8. На macOS і Linux йому потрібен [jq](https://jqlang.org);
   без нього рядок показує менше, але запис лімітів працює.

Необов'язкове, використовується, коли є:

- **[gh](https://cli.github.com)** — щоб читати посилання на issue або pull request GitHub, передане
  `/keel:start-task`.
- **Конектор Claude Code** для Jira, Linear чи Asana — щоб читати посилання на тікет. Без нього, а
  також із будь-яким посиланням, яке keel не може прочитати, keel просить вас вставити текст.
- **Сканери безпеки**, як-от [gitleaks](https://github.com/gitleaks/gitleaks) і
  [semgrep](https://semgrep.dev). Сканер, який названо в налаштуваннях проєкту, але якого немає на
  цьому ПК, — це гучне попередження в кожному звіті, а не провалена перевірка.

## Встановлення

У Claude Code (він запитає два налаштування нижче й [область встановлення](#область-встановлення)):

```
/plugin marketplace add mvbsoft/keel
/plugin install keel@keel
```

Якщо команди keel не з'явилися, виконайте `/reload-plugins` або перезапустіть Claude Code.

Або в терміналі, з налаштуваннями у вигляді опцій:

```bash
claude plugin marketplace add mvbsoft/keel
```

```bash
claude plugin install keel@keel --config conversation_language=en --config allow_opus=true
```

| Налаштування | Що робить | Типово |
|---|---|---|
| `conversation_language` | мова, якою keel говорить, звітує й пише плани (`en`, `uk`, `de`, ...); прохання про іншу мову в розмові діє для цієї розмови | `en` |
| `allow_opus` | вимкнено: кожен агент keel, який мав би працювати на Opus, працює на Sonnet | увімкнено |

Усі інші налаштування питає `/keel:configure`: [налаштування](settings.uk.md).

Потім відкрийте свій проєкт і запустіть `/keel:configure`
([Початок роботи](getting-started.uk.md#3-налаштування-проєкту-keelconfigure)).

### Область встановлення

Область визначає, де Claude Code вмикає keel. Панель `/plugin` питає про неї; у терміналі додайте
`--scope project` або `--scope local` (типово — user).

| Область | Хто отримує keel | Де Claude Code це записує |
|---|---|---|
| user (типово) | ви, у кожному проєкті на цьому ПК | `~/.claude/settings.json` |
| project | усі, хто працює в цьому репозиторії, щойно файл закомічено; кожен колега все одно один раз встановлює keel тією самою командою | `.claude/settings.json` |
| local | лише ви, лише в цьому репозиторії | `.claude/settings.local.json` |

Два налаштування вище в кожній області зберігаються для всього ПК; як проєкт отримує власні
значення: [налаштування](settings.uk.md#встановлення-для-одного-проєкту).

## Що keel змінює на вашому ПК і в проєктах

**Де діє keel.** keel працює лише в проєкті, який ви налаштували через `/keel:configure` (у ньому є
`.keel/config.json`). У будь-якому іншому проєкті:

- його хуки нічого не додають до розмови: ні робочих стандартів, ні рядка про мову, ні правил
  коментарів, ні попередження про контекст, ні підказок навичок, ні перевірки підписів ШІ;
- його агенти й дорадчі навички відхиляються, тож Claude Code використовує власні (агенти keel знову
  працюють, щойно в проєкті з'являється папка `.keel/`, наприклад під час `/keel:configure`);
- `/keel:configure` і `/keel:help` усе одно працюють.

Дві речі працюють у кожному проєкті, бо належать ПК: запис витрат (один рядок на початок розмови в
`~/.claude/keel/sessions.jsonl`, нічого для читання моделлю) і статус-рядок keel, якщо ви його
встановили. Якщо keel встановлено для вашого користувача, Claude Code усе одно показує його команди,
агентів і навички в кожному проєкті (їхні короткі описи). Щоб в інших проєктах не лишалося жодного
сліду, встановлюйте з `--scope project` або `--scope local`.

**На цьому ПК** keel пише:

- `~/.claude/keel/`: налаштування витрат ПК (`usage.json`), знімки лімітів плану (`limits.jsonl`,
  його попередня частина `limits.1.jsonl`, `limits-last.json`), дані витрат, прочитані з транскриптів
  для панелі (`usage-cache/`, `usage-index.json`, `keel-tasks.jsonl`, `sync-state.json`, останнє калібрування лімітів плану `calib-latest.json`), з якого гаманця платила кожна розмова (`sessions.jsonl`), проєкти, де ви
  підтвердили автономний git (`trusted-git.json`), вашу оновлену таблицю цін (`prices.json`, лише
  після оновлення цін, яке ви прийняли в `/keel:configure`; попередня — як `prices.json.bak`), скрипт статус-рядка (`statusline.js`) і
  папку плагіна для нього (`plugin-root.txt`);
- `~/.claude/settings.json`, лише після вашого «так» у `/keel:configure`: налаштування Claude Code,
  які ви прийняли, два налаштування keel (`pluginConfigs`) і статус-рядок, із резервною копією
  `settings.json.keel-backup-*` поруч.

**У проєкті**, лише після вашого «так» у `/keel:configure`: папка `.keel/`, ваші особисті
налаштування Claude Code для проєкту в `.claude/settings.local.json` (резервна копія в
`.keel/local/backups/`), рядок для цього файлу в `.gitignore`, коли git його ще не ігнорує, і
короткий розділ «Working with Claude Code» у README. Що лежить у `.keel/`:
[під капотом](under-the-hood.uk.md#що-keel-зберігає-у-вашому-проєкті).

## Оновлення

```bash
claude plugin marketplace update keel
```

```bash
claude plugin update keel@keel
```

Потім почніть нову розмову. Проєкт, чий `.keel/config.json` старший за нову версію, виправляє
`/keel:configure`: він питає лише про нові поля й зберігає все інше.

## Видалення

```bash
claude plugin uninstall keel@keel
```

```bash
claude plugin marketplace remove keel
```

Якщо встановлювали з `--scope project` або `--scope local`, додайте той самий `--scope` до команди
видалення.

keel також лишає таке, що можна прибрати вручну:

- **Статус-рядок.** Якщо keel встановив або обгорнув його, `statusLine` у `~/.claude/settings.json`
  досі вказує на `~/.claude/keel/statusline.js`, який тоді запускає вашу попередню команду (вона
  зберігається в `~/.claude/keel/usage.json` як `statusline.original`) або нічого не друкує.
  Поверніть стару команду або видаліть ключ `statusLine`.
- **`~/.claude/settings.json`**: налаштування Claude Code, які ви прийняли під час `/keel:configure`
  (`showClearContextOnPlanAccept`, `autoCompactWindow`, `bashOutputMaxChars`, `attribution`), запис
  keel у `pluginConfigs` і резервні копії `settings.json.keel-backup-*` поруч із файлом.
- **`~/.claude/keel/`** з усіма файлами, переліченими [вище](#що-keel-змінює-на-вашому-пк-і-в-проєктах).
- **У кожному проєкті**: `.keel/`; у `.claude/settings.local.json` — значення, які записав keel
  (`plansDirectory`, команди гейтів у `permissions.allow` і будь-які значення проєкту для
  налаштувань вище; резервна копія в `.keel/local/backups/`); рядок `.claude/settings.local.json`,
  який keel міг додати до `.gitignore`; і розділ «Working with Claude Code» у README.
- **Сторінка «keel usage»** у вашому акаунті claude.ai, якщо ви її створили.

## Усунення неполадок

- **«keel потребує Node.js 22 або новішої»** (ваш Node старіший) або хуки й команди keel не працюють,
  бо Node немає взагалі: встановіть Node 22+ із [nodejs.org](https://nodejs.org) і почніть нову
  розмову; перевірте командою `node --version`.
- **Статус-рядок порожній або показує мало на macOS чи Linux**: встановіть [jq](https://jqlang.org).
  Запис лімітів плану працює і без нього.
- **Звіт не показує відсотків плану**: keel дізнається ціну 1 % ваших лімітів із вимірювань
  статус-рядка; поки їх немає, він так і каже. У десктопному застосунку, де немає статус-рядка, keel
  наприкінці задачі питає застосунок. Подробиці:
  [панель витрат](usage-dashboard.uk.md#відсотки-лімітів-плану-і-калібрування).
- **keel зупиняється, бо git не довіряє папці** («dubious ownership», `git: refused`): папка
  проєкту належить іншому користувачеві, ніж той, від якого запущено git. keel називає власне
  виправлення git; виконайте його самі, якщо довіряєте папці:
  `git config --global --add safe.directory "<folder>"`.
- **Команда keel просить запустити `/keel:configure`**: у проєкті ще немає `.keel/config.json` або
  він застарів; configure виправляє лише те, чого бракує.
- **keel нічого не робить у проєкті** (немає стандартів на початку розмови, його агенти
  відхиляються): проєкт не налаштовано; запустіть `/keel:configure`.
- **Оновлення не надходить**: виконайте дві команди оновлення вище й почніть нову розмову.
- **Хук проєкту відхиляє скрипти keel**: keel зупиняється й пояснює; він пропонує вузький виняток для
  `node`, що запускає файл у власній папці `scripts/` keel, або ви лишаєте хук як є.
- **Claude Code питає дозволу запустити крок keel.** Скрипти keel працюють без запиту лише в простій
  формі, яку використовує keel (`node "<keel>/scripts/<name>.js" "<project>" ...`); будь-яка інша
  форма (опції node, `env`, `bash -c`, об'єднані команди, у PowerShell `--%` або порожній аргумент)
  відхиляється, і keel надсилає її ще раз у простій формі
  ([під капотом](under-the-hood.uk.md#безпека)); читання скрипта keel через `grep` чи `sed` іде за
  вашими звичайними дозволами. Деякі кроки питають навмисно, щоразу:
  - кроки, що пишуть поза власними папками keel: застосування налаштувань Claude Code, перенесення
    іншої системи нотаток у keel і налаштування витрат (його налаштування, оновлення цін,
    встановлення статус-рядка);
  - в автономному git — кроки git, доки ви не підтвердите автономний git для проєкту на цьому ПК (і
    знову після зміни налаштувань git проєкту), а також пуш із головної гілки;
  - підтвердження, що починаються з «keel:»: завершення або прибирання задачі (її папка йде в кошик
    keel), видалення гілки, очищення кошика, підтвердження автономного git і злиття (якщо
    `git.ask_before_merge` не вимкнено в підтвердженому автономному режимі).

  Чому кожен крок захищено: [як поводиться keel](behavior.uk.md).
